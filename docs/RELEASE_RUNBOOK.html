Rollback if needed

Stop rollout and record the failed step. Preserve audit evidence. Core rollback order is console → gateway; Intelligence has its own destructive-migration recovery boundary.

Only if needed

Before reverting an embedded-capable gateway, stop creating embedded requests and let outstanding approvals expire or resolve under the new gateway; an older gateway does not enforce the new application-credential provenance checks. Disable the relying applications during this interval. Redeploy the previous console SHA, then the previous gateway SHA, through the normal approved workflows.

Keep additive tables/columns and enum values. Do not delete audit rows. Drain pending WORKSPACE_CREATED notices, or set OPERATOR_NOTIFY_CHANNEL=off before reverting a gateway that cannot read that enum. Restore marketing by promoting its previous Vercel deployment.

Only if needed

The sign-in/configuration migrations drop columns and old invitation/ceremony tables and clear sessions/pending actions. Rolling back only the image is not sufficient. Stop app and scheduler. Prefer a forward fix; otherwise restore a reviewed pre-upgrade database backup together with its matching old image, environment and encryption key, accounting for writes since the backup. Do not recreate approvals or sessions from client data.
